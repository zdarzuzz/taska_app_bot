# TASKA 0.10 — Telegram Mini App

## Настройка 0.10

1. В SQL Editor запусти migration-10.sql полностью. Требуется уже установленная migration-09.sql. Старые записи не удаляются.
2. Назначь модератора вручную через Table Editor → users: найди свой подтверждённый аккаунт по telegram_id, установи is_moderator = true только в своей строке. Никогда не давай этот доступ автоматически по имени пользователя. В приложении после повторного входа появится вкладка «Проверка».
3. Обнови существующую Edge Function taska-api файлом taska-api.ts; оставь её настройки авторизации как были. Затем обнови пять файлов фронтенда на GitHub Pages.
4. На двух аккаунтах проверь публикацию (сначала moderation, после одобрения open), возврат с причиной и повторную отправку, отклик, выбор и старт, сдачу ссылки, правки, повторную сдачу, принятие, подтверждение оплаты и отзывы обоих участников.

Оплата: встроенного платежного провайдера нет. Заказчик отмечает перевод вне приложения, исполнитель подтверждает только фактическое поступление; задача закрывается после обоих действий. Это учёт заявлений сторон, а не подтверждение банковской операции, эскроу или гарантия возврата. Не переводите реальные деньги ради проверки; в закрытом тесте используйте согласованный учебный сценарий без подтверждения ложной оплаты. Для настоящих платежей отдельно требуется провайдер, договор, его серверная интеграция и проверка требований к работе с персональными данными. Существующие опубликованные задачи не переводятся автоматически на модерацию.

## Настройка 0.9

1. В Supabase SQL Editor открой New query, вставь полностью `migration-09.sql` и нажми Run. Миграция не удаляет прежние таблицы или записи; добавляет настройку уведомлений и серверные функции с атомарными проверками принадлежности.
2. В Edge Functions → taska-api → Code замени код содержимым `taska-api.ts`, нажми Deploy updates. Проверь, что Verify JWT with legacy secret остаётся выключенным: подпись Telegram проверяется самой функцией. `telegram-auth` и секреты не меняй.
3. В GitHub Pages обнови пять файлов: index.html, app.js, telegram.js, styles.css, mini-app.css. SQL и TypeScript предназначены только для Supabase.
4. Полностью закрой Mini App и открой её вновь из бота. На двух разных Telegram-аккаунтах проверь: заказчик публикует, студент откликается, заказчик открывает переписку, студент отвечает, заказчик выбирает исполнителя, студент подтверждает, заказчик начинает работу. Оба пользователя включают уведомления на вкладке «События», предварительно запустив чат бота. Проверь таблицы applications, conversations, messages, notifications, notification_outbox.

Чат и события обновляются на открытом экране раз в 8 секунд, без прерывания ввода. Уведомления внутри ТАСКИ записываются транзакционно; отправка ботом производится сразу после события, только при включённой настройке получателя. Если Telegram отклонит отправку, запись останется в notification_outbox со статусом failed; автоматический повтор пока не подключён. Реальные платежи, сдача/приёмка и отзывы ещё не подключены; пользовательские данные остаются на сервере. Открытая тестовая версия не предназначена для обработки реальных чувствительных данных. Действие Telegram initData ограничено десятью минутами, после истечения требуется переоткрыть Mini App.

## Настройка 0.8 (обязательно перед публикацией фронтенда)

1. В Supabase Edge Functions создай функцию `taska-api` через редактор, вставь содержимое файла `taska-api.ts` в index.ts, нажми Deploy. Токен из ранее сохранённого `TELEGRAM_BOT_TOKEN` используется автоматически. Существующую `telegram-auth` не меняй.
2. Только после установки кода отключи Verify JWT with legacy secret у `taska-api` и сохрани. Сервер самостоятельно проверяет подписанные Telegram initData в каждом запросе и не доверяет пользовательским ID из клиента. Не добавляй секретные ключи в GitHub.
3. Загрузи на GitHub Pages только фронтенд: index.html, app.js, telegram.js, styles.css, mini-app.css. Файл taska-api.ts нужен только для редактора Edge Functions. Дождись публикации, полностью закрой Mini App, открой через @taska_app_bot.
4. Создай профиль заказчика, сохрани черновик или опубликуй полноценную задачу, проверь таблицы profiles и tasks. С другого Telegram-аккаунта создай профиль студента, открой ленту и отправь отклик. Заказчик увидит отклик после повторного открытия раздела «Задачи». Проверь applications.

Ограничения: для закрытого тестирования, пока не проверены интеграция и безопасность реальных персональных данных. Авторизация запросов действует 10 минут с момента открытия Mini App, затем нужно переоткрыть приложение. Черновики отправляются на сервер явно кнопкой сохранения, а не при каждом вводе. Выбор исполнителя, переписка, приёмка, отзывы, уведомления и платежи ещё не подключены. Публикация — прямое открытие в ленте без модерации. Не публикуй реальные личные данные или материалы до проверки политики приватности и размещения данных.

## Подключение авторизации 0.7

Фронтенд вызывает `https://utinwfxyouyuxbjlysnp.supabase.co/functions/v1/telegram-auth` при каждом открытии из Telegram. Функция должна проверять подписанные Telegram initData, сохранять аккаунт в users и возвращать `{user: {id, telegram_id, username, display_name}}`. Legacy JWT для этой функции отключён, проверка подписи выполняется внутри функции. При ошибке приложение не открывает локальный кабинет. В браузере вне Telegram доступен автономный интерфейс. Профили и черновики пока локальные, при входе из Telegram они разделены по подтверждённому UUID пользователя; старые данные 0.6 не переносятся автоматически. UUID не является серверным токеном авторизации. Синхронизация задач, профилей, сообщений и отправка уведомлений ещё не внедрены.

После публикации файлов на GitHub Pages закрой Mini App полностью и открой снова из @taska_app_bot. В Supabase → Table Editor → users должна появиться строка с твоим аккаунтом. Не отправляй скриншот с приватными данными или секретами.

## Как создать своего бота и подключить приложение

1. Открой @BotFather, отправь `/newbot`, выбери название и свободный username, который заканчивается на `bot`. Сохрани токен в безопасном месте. Не отправляй его в чат и не коммить в GitHub.
2. Опубликуй эту версию фронтенда на HTTPS (например, GitHub Pages). Для репозитория `zdarzuzz/TASKA` это будет `https://zdarzuzz.github.io/TASKA/`, если публикация настроена на корень main. До подключения API используй ссылку только для закрытой проверки.
3. В @BotFather отправь `/setmenubutton`, выбери нового бота, введи название кнопки `Открыть ТАСКУ` и HTTPS-ссылку.
4. Открой чат бота, нажми кнопку. В «Событиях» можно запросить разрешение Telegram на сообщения, но реальная отправка требует сервера.
5. Не помещай токен бота или Supabase service_role в GitHub Pages, JS или Figma. Секреты будут переменными окружения Node.js на сервере.

## Предлагаемая архитектура реального MVP

- Фронтенд: этот HTML/CSS/JS + Telegram Web App SDK.
- API: Node.js (например, на существующем VPS), HTTPS. При входе клиент отправляет `Telegram.WebApp.initData`, сервер проверяет подпись по официальному алгоритму Telegram, свежесть `auth_date` и создаёт короткоживущую сессию. Не доверять `initDataUnsafe`, роли, статусу и идентификаторам из клиента.
- Хранилище: Supabase/PostgreSQL, миграции, ограничение доступа по участникам сделки. При прямом доступе клиентов необходимы RLS. Привилегированный ключ должен оставаться только на сервере.
- Сервис уведомлений: после успешной транзакции создаётся запись в `notifications` и очередь доставки. Сервер отправляет разрешённому получателю уведомление через Bot API `sendMessage`; ошибки доставки повторяются с ограничением, состояние прочтения сохраняется отдельно.

| Таблица | Основные поля |
|---|---|
| users | id, telegram_id unique, display_name, created_at |
| profiles | id, user_id, role, name, about, skills, portfolio |
| tasks | id, owner_profile_id, title, description, category, budget, deadline, status |
| applications | id, task_id, student_profile_id, message, status, unique(task_id, student_profile_id) |
| conversations | id, task_id, customer_profile_id, student_profile_id |
| messages | id, conversation_id, sender_profile_id, body, created_at |
| submissions | id, task_id, version, link, comment, created_at |
| notifications | id, recipient_user_id, task_id, event_type, read_at, created_at |
| notification_outbox | notification_id unique, delivery_status, attempts, next_attempt_at |
| reviews | id, task_id, author_profile_id, target_profile_id, rating, body |

Порядок внедрения: создание бота → авторизация → профили → задачи и отклики → чат → события и очередь уведомлений → бот → интеграционные тесты двух реальных пользователей. Проверять права и допустимые переходы статусов на сервере. Не имитировать платежи; подключение платежей — отдельный этап.
